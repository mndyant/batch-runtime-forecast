# 設計レビューの反映
Claude Opusに仕様書を読み取り専用でレビュー依頼。全文はclaude-design-review.txt。

採用した点：
- 選択はケース単位。開発7日MAEのみ。α10、学習120日、ラグ28日を事前固定。
- 改善率の分母を候補1「直近4週の同曜日平均」に統一。
- 日跨ぎ、状況判定、完了・最終着手誤差の式を固定。
- 件数0日を除いた指標・締切混同行列も最終報告に記録。平均手法は0日を含める。
- 30日先を手法選択に使用しない。重なり・待ち行列・欠損日は自動推測しない旨を明示。

採用しなかった提案と理由：
- 所要時間再帰の禁止：未来実績を入力しなければ時間分割に反しない。速度変化の追随を試す候補として残し、累積誤差を監査する。30日で良好な結果を保証しない。
- 0件が多い場合に候補3を同曜日平均へ置換：α>0のリッジは定数列でも解ける。候補の定義を保ち、選択手順が単純手法を選べる構成にする。全0入力の有限性をテスト。
- 実未来件数を使う補助採点：初版では正解を渡す経路を増やさず、件数MAEと所要時間MAEを併記する。
- 欠損日に0を自動補充：欠損と休止は異なるため拒否する。利用者が確認できる休止日だけ0件で入力する。
- 31水準日付ダミー：元から使わず、sin/cos・月初/月末の少数特徴。曜日7ダミーは正則化で解く。

## Claude Sonnetのコードレビュー
全文はclaude-code-review.txt。評価経路の確認に加え、再帰予測の上限超過を指摘された。予測を上限へ丸めると過小な計画を出すため、10億件・10080分超過時は明示エラーにして失敗を記録する方針とした。テストで上限超過を確認。汎用例外を400へ変える提案は、プログラム障害を利用者の入力エラーにしないため不採用。

探索・監査結果を見たパラメータ探索は初版で実施しない。最終seed100〜119の採点前に固定コードとデータをハッシュ化する。
