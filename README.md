# バッチ完了時刻・締切予測

日次の処理件数と所要時間から、今後の完了日時・締切超過・安全余裕を確保する最終着手日時を計算するローカルWebアプリです。22:00開始・翌日00:00締切など、日付をまたぐ計画を扱います。

**[短い操作デモ](docs/demo.md#短い操作デモ) · [評価結果](docs/evaluation.md) · [設計判断](docs/design-decisions.md)**

![実績・締切・着手日時を確認する操作デモ](docs/images/batch-demo.gif)

## まず試す

1. 「曜日差」などの合成サンプルを選び、「予測を実行」を押します。
2. 締切超過日数と最終着手日時を確認します。**最終着手日時 = 締切 − 予測所要時間 − 安全余裕**です。
3. 日別表で日跨ぎを確認し、サマリTXT・予測CSV・結果JSONを保存します。

## 実装で工夫したこと

| 判断 | 実装・確認方法 |
|---|---|
| 日跨ぎを曖昧にしない | 締切が開始時刻以下なら翌日。同時刻なら24時間後。日時を日付付き・日本時間で表示 |
| 手法を評価してから選ぶ | 同曜日平均・7日平均・回帰を比較し、開発区間の評価で選択。監査区間では選び直さない |
| 予測入力と正解を分ける | 未来の件数・所要時間を学習へ渡さず、凍結後に未使用seedで全候補を採点 |
| 入力と出力の状態を揃える | CSVの不正値・欠損・重複を検証。条件変更後は古い結果の保存を止める |

**Python / Flask / NumPy / pandas / HTML / CSS / JavaScript / SVG**。実行時のAPIキー・LLM接続・クラウド契約は不要です。

## 評価と限界

合成データ6シナリオ・120ケースの7日間MAEは、同曜日平均**23.45分 → 選択手法18.84分（19.7%改善）**でした。一方、締切超過190件中**48件の見逃し・64件の誤警報**が残り、突発増加では基準より4.7%悪化しました。

実業務データでの有効性は未検証です。1ジョブ・暦日の計画が対象で、祝日・依存ジョブ・並列処理・待ち行列は扱いません。倍率比較は条件比較で、確率付き予測区間ではありません。[評価条件・悪化ケース・全候補の結果](docs/evaluation.md)を公開しています。

## ローカルで動かす

Python 3.14.3での既存検証記録があります。PowerShellの例です。

```powershell
git clone https://github.com/mndyant/batch-runtime-forecast.git
cd batch-runtime-forecast
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
.\.venv\Scripts\python run.py
```

`http://127.0.0.1:5001` を開きます。初回の依存インストール後はオフラインで利用できます。入力はUTF-8の `date,records,runtime_minutes`、連続150〜3650日、2MB以内です。
